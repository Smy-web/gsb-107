# 青少年编程夏令营 · 展示会 AI 评语生成子系统

## 这个仓库是什么

为期两周的青少年编程夏令营，结营那天每组孩子上台展示自己的 Scratch / Python 作品，现场录音转写成带说话人的文字，导师在后台填技术点评和一句话评语，然后由大模型把这些素材揉成四段给家长和教务看的文字，最后拼成一封家长邮件发出去。

这里裁剪出来的只有「大模型生成评语」这一段：录音转写、说话人分离、Web 路由、邮件发送都不在范围内，不要去找它们。上游调用方是夏令营后台的 Flask 服务，它按下面写死的形状调这个模块，改不得。

## 目录

- `backend/ai_feedback_generator.py` — 本次要处理的模块，就这一个文件。

`backend` 没有 `__init__.py`，按命名空间包用。验证命令必须从仓库根目录、用 `-m` 的形式跑，这样仓库根才会进 `sys.path`，`from backend.ai_feedback_generator import AIFeedbackGenerator` 才解析得到。

## 运行环境

教务内网机器，离线。`~/venvs/gsb-camp` 里只有 `requirements-task.txt` 列出来的包，`openai` 装了，但**没有配 `OPENAI_API_KEY`，也不允许联网**——不要去真的调模型。测试里必须用替身把 `self.client.chat.completions.create` 顶掉，喂你自己造的返回文本，断言模块解析出来的结果。替身要能捕获模块实际发出去的 `messages`，别写一个什么都不检查就返回固定值的替身。

## 调用方怎么用这个模块（硬约定）

上游 Flask 服务里有两处调用，两处都按位置参数或下面这些关键字参数传：

```
AIFeedbackGenerator(Config.OPENAI_API_KEY)      # 构造，只在配了 key 的时候构造

gen.generate_feedback(
    project_title=...,        # str，作品名，例如「海底世界」
    project_description=...,  # str，孩子自己写的一句话简介
    student_names=...,        # str，一组孩子的名字，逗号分隔
    project_type=...,         # str，scratch / python / 硬件
    transcript=...,           # str，带说话人标记的展示会转写，可能是空串
    technical_feedback=...,   # str，导师手填的技术点评，可能是空串
    mentor_comments=...,      # List[str]，其他导师的一句话评语，可能是 None
)

gen.generate_email_content(
    student_names=..., project_title=..., warm_feedback=..., ai_summary=...
)
```

## 输出契约

`generate_feedback` 返回一个 dict，**恒有且只有这四个键**，值都是 str（不允许 None）。上游把四个值原样落到 `presentations` 表的四个列，前端四个栏目分别取：

| 键 | 前端栏目 | 内容 |
| --- | --- | --- |
| `technical_feedback` | 技术点评 | 模型输出的第一段原文，完整保留，不删行不改写 |
| `improvement_suggestions` | 改进建议 | 第一段里「改进 / 建议」那一部分 |
| `ai_summary` | 项目简介 | 模型输出的第二段，150–200 字的项目内容摘要，完整保留 |
| `warm_feedback` | 老师的话 | 模型输出的第三段，300–400 字、给家长看的温暖评语 |

四条是硬的：

1. 四个键任何情况下都在，缺一个上游就 `KeyError`。
2. `technical_feedback`、`ai_summary`、`warm_feedback` 三者分别对应模型输出的第一、二、三段，不得互相串位。特别地，`improvement_suggestions` 与 `ai_summary` **不允许是同一段文本**——现在的实现在模型少写一段时就会把摘要同时塞进这两栏，前端两个栏目显示一模一样的话。
3. 第一段和第三段是给人看的成稿，不许做「按行筛选」或「截断到 N 行」这类加工；第二段的字数口径由模型的 prompt 约束，解析这一侧不负责裁剪。
4. `improvement_suggestions` 是从第一段里切出来的那一部分，切点要落在「改进」或「建议」这个标题的**开头**，不是标题中间，也不能把标题前面的技术亮点整段带进来。

`generate_email_content` 返回 `{"subject": str, "body_html": str}`：

- `subject` 必须是**单行**、可直接当邮件主题用的文字：不含换行，不含「主题：」「Subject:」这类前缀标签，两侧不留空白。
- `body_html` 必须是分隔符之后的**全部**正文，正文里自己出现的分隔线不能被当成分段点砍掉后半截。
- 模型没给出分隔符时，`subject` 与 `body_html` 不允许是同一段内容；这种情况下取什么当主题、正文给什么，是一个需要你定下来的口径。

## 分段协议

两个方法的 prompt 都要求模型「用 `---` 分隔」输出。真实模型不老实，下面这些都在生产日志里出现过，解析必须都能给出确定的结果：

- 分隔符写成 `----`、`-----`，或者分隔符前后有空格、有多个空行；
- 正文里自己有一条 Markdown 水平线 `---`（第三段温暖评语里尤其常见）；
- 只给了两段（第三段没写），或者一段都没有；
- 整段输出是空字符串；
- `message.content` 是 `None`（被内容策略拦下时就是这样）；
- `finish_reason` 是 `length`，也就是被 `max_tokens` 截断、评语停在半句。

**分隔符到底怎么识别、正文里的水平线怎么区分、段数不足时怎么降级**，这三件事是本模块最要紧的口径，也是评审要看的取舍。你选一种，把选择和理由写进下面「本次做题人填写」那一节，并让实现和文档一致。降级口径必须让调用方能分辨「模型没写第三段」和「模型写了但内容是空的」，怎么分辨由你定。

任何情况下都不得抛出未捕获的异常给上游：上游会把异常原文拼进 `生成反馈失败: {...}` 直接返回给前端，运维看到的是一句 `'NoneType' object has no attribute 'strip'`，什么信息都没有。要么返回确定的降级结果，要么抛一个带可读原因的自定义异常，选一种写进 README。

`mentor_comments` 是老数据迁移过来的，列表里可能混进 `None` 或非字符串元素，不得因此整体失败。

## 已知问题（另有排期，别顺手修）

下面这些确实是问题，但已经排到下个迭代，本次不验收，也不要动：

- 模型名、`temperature`、`max_tokens` 硬编码在方法体里，没有超时、没有重试、没有失败退避。
- 展示会转写原文直接拼进 prompt，孩子在台上说一句「忽略以上指令」就能影响模型输出。
- `api_key` 传 `None` 时构造函数直接抛 `OpenAIError`；上游负责在没配 key 时不构造这个对象。
- 上游 Flask 服务把这个模块的任何异常都转成 HTTP 500 加一句 `生成反馈失败: {...}`，不区分「模型没配」「模型超时」「输出解析不了」。
